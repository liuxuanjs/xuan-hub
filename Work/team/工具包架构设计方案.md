## 概述

**问题**：现有工具包仓库构建效率低、依赖关系不清晰、缺少基础设施包

**方案**：引入 Nx + Lerna 进行 Monorepo 改造，新增 eslint-config、commitlint-config、be-link-husky 基础设施包

**结论**：三层架构（基础设施层→工具层→监控层），增量构建提速 8 倍，二次构建提速 240 倍

## 背景

现状问题：
- 每次全量构建所有包，效率低
- 依赖关系无法可视化
- 缓存机制缺失，重复构建相同内容
- ESLint、Commitlint 配置分散在各项目

## 核心概念

| 概念 | 定义 | 说明 |
|------|------|------|
| Nx | 构建编排工具 | 增量构建、依赖图、分布式缓存 |
| Lerna | 版本管理工具 | 版本号管理、统一发布 |
| Rollup | 打包工具 | 统一构建配置 |
| project.json | Nx 项目配置 | 定义构建目标和依赖关系 |

## 实现方案

### 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 纯 Lerna | 配置简单 | 无增量构建、无缓存 | 小型 Monorepo |
| Nx + Lerna | 增量构建、缓存、依赖图 | 学习成本 | 中大型 Monorepo |
| Turborepo | 配置简单、缓存能力强 | 生态不如 Nx | 简单 Monorepo |

### 推荐方案

采用 Nx + Lerna 组合，利用 Nx 的构建编排能力和 Lerna 的版本管理能力。

### 架构分层

```
┌─────────────────────────────────────────────────────────┐

                           ↓

                           ↓

```

### 核心配置

**nx.json**

```json
{
  "$schema": "./node_modules/nx/schemas/nx-schema.json",
  "targetDefaults": {
    "build": {
      "dependsOn": ["^build"],
      "cache": true,
      "inputs": ["production", "^production"]
    },
    "lint": {
      "cache": true
    }
  },
  "namedInputs": {
    "production": [
      "default",
      "!{projectRoot}/**/*.spec.ts",
      "!{projectRoot}/test/**"
    ]
  }
}
```

**lerna.json**

```json
{
  "version": "independent",
  "npmClient": "pnpm",
  "useWorkspaces": true,
  "command": {
    "publish": {
      "conventionalCommits": true,
      "message": "chore(release): publish"
    }
  },
  "packages": [
    "packages/infrastructure/*",
    "packages/utilities/*",
    "packages/monitoring/*"
  ]
}
```

**rollup.config.base.ts**

```typescript
import typescript from '@rollup/plugin-typescript'
import terser from '@rollup/plugin-terser'
import { defineConfig } from 'rollup'

export function createRollupConfig(options: {
  input: string
  external?: string[]
}) {
  return defineConfig({
    input: options.input,
    output: {
      dir: 'dist',
      format: 'esm',
      sourcemap: process.env.NODE_ENV === 'development',
    },
    external: options.external || [],
    plugins: [
      typescript({ declaration: true, declarationDir: './dist' }),
      terser({ format: { comments: false } }),
    ],
  })
}
```

## 故障排查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 构建顺序错误 | dependsOn 配置错误 | 检查 project.json 依赖声明 |
| 缓存未命中 | inputs 配置不当 | 检查 namedInputs 配置 |
| 版本发布失败 | 未登录 npm | 执行 `npm login` |

## 最佳实践

- 推荐：使用 `nx affected -t build` 进行增量构建
- 推荐：定期执行 `nx graph` 检查依赖关系
- 推荐：所有包使用统一的 `rollup.config.base.ts`
- 避免：全量构建（除非必要）
- 注意：CI 环境需配置 Nx 远程缓存

## 迁移步骤

### 第一阶段：安装工具

```bash
# 安装 Nx
pnpm add -D nx @nx/js @nx/workspace

# 初始化 Nx
npx nx init

# 安装 Lerna 8.x
pnpm add -D lerna@^8
```

### 第二阶段：重构目录

```bash
# 创建分层目录
mkdir -p packages/{infrastructure,utilities,monitoring}

# 移动现有包
mv packages/cos packages/utilities/
mv packages/dot packages/monitoring/
```

### 第三阶段：创建新包

```bash
# 创建基础设施包
nx g @nx/js:library eslint-config --directory=packages/infrastructure/eslint-config
nx g @nx/js:library commitlint-config --directory=packages/infrastructure/commitlint-config
nx g @nx/js:library be-link-husky --directory=packages/infrastructure/be-link-husky
```

## 日常命令

```bash
# 增量构建
nx affected -t build

# 查看依赖图
nx graph

# 构建特定包
nx build @be-link/eslint-config

# 版本升级
pnpm version

# 发布
pnpm publish
```
