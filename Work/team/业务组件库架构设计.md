## 概述

**问题**：业务组件分散在各项目中，缺乏统一管理和复用机制

**方案**：基于 Nx + Lerna + Rollup 构建 Monorepo 组件库，分别封装 PC 端和移动端组件

**结论**：采用双包架构（@be-link/antd + @be-link/antd-mobile），独立仓库管理

## 背景

团队存在大量重复的业务组件代码，PC 端基于 Ant Design 5.x，移动端基于 Ant Design Mobile 5.x。需要统一封装为可复用的 npm 包，提升开发效率。

## 核心概念

| 概念 | 定义 | 说明 |
|------|------|------|
| @be-link/antd | PC端组件包 | 基于 Ant Design 5.x 封装 |
| @be-link/antd-mobile | 移动端组件包 | 基于 Ant Design Mobile 5.x 封装 |
| Nx | 构建编排工具 | 提供增量构建、依赖图、缓存 |
| Lerna | 版本管理工具 | 统一版本发布、Changelog 生成 |

## 实现方案

### 技术选型

| 工具 | 版本 | 用途 |
|------|------|------|
| Node | 18+ | 运行环境 |
| pnpm | 8+ | 包管理器 |
| Nx | 19.x | 构建编排 |
| Lerna | 8.x | 版本管理 |
| Rollup | 4.x | 打包工具 |

### 目录结构

```
be-link-components/
├── packages/
│   ├── antd/                    # PC端组件
│   │   ├── src/
│   │   │   ├── Button/
│   │   │   ├── Form/
│   │   │   └── index.ts
│   │   ├── project.json
│   │   └── package.json
│   └── antd-mobile/             # 移动端组件
│       ├── src/
│       └── package.json
├── apps/
│   └── docs/                    # 文档站点（Docusaurus）
├── nx.json
├── lerna.json
├── pnpm-workspace.yaml
└── package.json
```

### 包配置示例

```json
// packages/antd/package.json
{
  "name": "@be-link/antd",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "peerDependencies": {
    "react": "^18.0.0",
    "antd": "^5.0.0"
  }
}
```

## 故障排查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 构建失败 | 依赖版本不匹配 | 检查 peerDependencies 版本 |
| 类型缺失 | 未生成 .d.ts | 检查 rollup typescript 插件配置 |
| 样式丢失 | Less 未处理 | 配置 rollup-plugin-postcss |

## 最佳实践

- 推荐：组件使用 peerDependencies 声明基础库依赖
- 推荐：使用 `nx affected -t build` 进行增量构建
- 避免：将 react/antd 打包进组件产物
- 注意：发布前执行 `nx graph` 确认依赖关系正确

## 日常命令

| 命令 | 说明 |
|------|------|
| `nx build @be-link/antd` | 构建 PC 组件包 |
| `nx affected -t build` | 增量构建 |
| `nx graph` | 查看依赖图 |
| `pnpm version` | 升级版本 |
| `pnpm publish` | 发布到 npm |
