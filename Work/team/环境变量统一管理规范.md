## 规范说明

### 命名规范

**格式**：`VITE_<分类>_<具体配置>`

| 分类 | 示例 |
|------|------|
| `VITE_APP_*` | 应用基础信息 |
| `VITE_API_*` | API 相关配置 |
| `VITE_<服务名>_*` | 第三方服务（如 `VITE_MAP_KEY`） |
| `VITE_ENABLE_*` | 功能开关 |

命名规则：
- 必须以 `VITE_` 开头（Vite 要求）
- 全大写，下划线分隔
- 语义化，见名知意

### 文件加载顺序

```
# pnpm dev（开发模式）
.env → .env.local → .env.development → .env.development.local

# pnpm build（生产模式）
.env → .env.local → .env.production → .env.production.local

# 后加载的会覆盖先加载的
```

## 操作步骤

### 阶段一：创建环境文件

**项目根目录结构**

```
项目根目录/
├── .env                    # 基础配置（所有环境共享）
├── .env.development        # 开发环境配置
├── .env.test               # 测试环境配置
├── .env.production         # 生产环境配置
├── .env.local              # 本地私有配置（不提交 Git）
└── src/
    ├── types/
    │   └── env.d.ts        # 类型定义
    └── config/
        └── env.ts          # 配置工具类
```

**.env**（基础配置）

```bash
# 基础配置（所有环境共享）
VITE_APP_NAME=my-app
VITE_APP_VERSION=$npm_package_version
VITE_CDN_URL=https://cdn.example.com
```

**.env.development**

```bash
# 开发环境配置
```

### 阶段二：创建类型定义

**src/types/env.d.ts**

```typescript
/// <reference types="vite/client" />

/**
 * 环境变量类型定义
 * 每次添加新的环境变量，必须在这里添加类型定义
 */
interface ImportMetaEnv {
  // 应用基础信息
  readonly VITE_APP_NAME: string
  readonly VITE_APP_VERSION: string

  // API 配置
  readonly VITE_API_BASE_URL: string
  readonly VITE_API_TIMEOUT: string

  // 第三方服务
  readonly VITE_MAP_KEY: string

  // CDN 配置
  readonly VITE_CDN_URL: string

  // 功能开关
  readonly VITE_ENABLE_MOCK: 'true' | 'false'
  readonly VITE_ENABLE_VCONSOLE: 'true' | 'false'
  readonly VITE_BUILD_SOURCEMAP: 'true' | 'false'
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

### 阶段三：创建工具类

**src/config/env.ts**

```typescript
/**
 * 环境配置工具类
 * 使用：import { env } from '@/config/env'
 */
class EnvConfig {
  // 应用信息
  get appName(): string {
    return import.meta.env.VITE_APP_NAME
  }

  get appVersion(): string {
    return import.meta.env.VITE_APP_VERSION
  }

  // 环境判断
  get isDev(): boolean {
    return import.meta.env.DEV
  }

  get isProd(): boolean {
    return import.meta.env.PROD
  }

  get isTest(): boolean {
    return import.meta.env.MODE === 'test'
  }

  // API 配置
  get apiBaseUrl(): string {
    return import.meta.env.VITE_API_BASE_URL
  }

  get apiTimeout(): number {
    return this.toNumber(import.meta.env.VITE_API_TIMEOUT, 10000)
  }

  // 第三方服务
  get mapKey(): string {
    return import.meta.env.VITE_MAP_KEY
  }

  // 功能开关
  get enableMock(): boolean {
    return this.toBoolean(import.meta.env.VITE_ENABLE_MOCK)
  }

  get enableVConsole(): boolean {
    return this.toBoolean(import.meta.env.VITE_ENABLE_VCONSOLE)
  }

  // 私有工具方法
  private toBoolean(value: string | undefined): boolean {
    return value === 'true'
  }

  private toNumber(value: string | undefined, defaultValue: number = 0): number {
    const num = Number(value)
    return isNaN(num) ? defaultValue : num
  }

  // 验证必需的环境变量
  validate(): void {
    const required: Array<keyof ImportMetaEnv> = [
      'VITE_APP_NAME',
      'VITE_API_BASE_URL',
    ]

    const missing = required.filter(key => !import.meta.env[key])

    if (missing.length > 0) {
      throw new Error(`缺少必需的环境变量: ${missing.join(', ')}`)
    }
  }

  // 打印当前配置（仅开发环境）
  printConfig(): void {
    if (!this.isDev) return

    console.group('环境配置')
    console.log('环境:', import.meta.env.MODE)
    console.log('应用:', this.appName)
    console.log('API:', this.apiBaseUrl)
    console.groupEnd()
  }
}

export const env = new EnvConfig()

// 应用启动时验证
if (import.meta.env.MODE !== 'test') {
  env.validate()
  env.printConfig()
}
```

```json
{
```

## 回滚方案

### 触发条件

- 环境变量加载失败
- 配置冲突无法解决

### 回滚步骤

```bash
# 1. 删除环境配置文件
rm .env .env.development .env.test .env.production

# 2. 删除类型定义和工具类
rm src/types/env.d.ts src/config/env.ts

# 3. 恢复代码中的硬编码
git checkout src/
```

## 常见问题

### Q1: 环境变量不生效

**检查清单**：

1. 检查前缀：必须以 `VITE_` 开头
2. 重启开发服务器：修改 `.env` 后必须重启 `pnpm dev`
3. 检查文件位置：必须在项目根目录
4. 检查语法：等号两边不能有空格

```bash
# 正确
VITE_API_URL=https://api.example.com

# 错误
VITE_API_URL = https://api.example.com
```

### Q2: Vite 项目需要安装 dotenv 吗

**不需要**。Vite 内置支持 `.env` 文件。

### Q3: 需要 cross-env 吗

**不需要**。Vite 的 `--mode` 参数本身就是跨平台的。

```json
// 推荐
"build:test": "vite build --mode test"

// 不推荐
"build:test": "cross-env NODE_ENV=test vite build"
```

### Q4: 为什么用工具类而不是直接访问

- IDE 自动补全，避免拼写错误
- 类型安全，编译时检查
- 自动类型转换（string → boolean/number）
- 统一管理，便于维护

```typescript
// 推荐
import { env } from '@/config/env'
const apiUrl = env.apiBaseUrl

// 不推荐
const apiUrl = import.meta.env.VITE_API_BASE_URL
```

### Q5: 如何在 CI/CD 中配置

**GitHub Actions**

```yaml
- name: Build
  run: pnpm build
  env:
    VITE_MAP_KEY: ${{ secrets.MAP_KEY }}
```

### Q6: 本地配置被覆盖

创建 `.env.local` 或 `.env.development.local` 可以覆盖默认配置，且不会提交到 Git。

## 添加新配置的步骤

1. 在所有 `.env.*` 文件中添加配置项
2. 在 `env.d.ts` 中添加类型定义
3. 在 `env.ts` 中添加 getter 方法
4. 替换代码中的硬编码
5. 测试功能是否正常
