## 核心结论

**同源策略**：浏览器的安全机制，限制不同源之间的资源访问。

**同源条件**：协议 + 域名 + 端口 **完全相同**

```
https://www.example.com:443/path
  │          │           │
 协议       域名        端口（三者必须都相同）
```

## 同源判断示例

以 `https://www.example.com` 为基准：

| URL | 是否同源 | 原因 |
|-----|---------|------|
| `https://www.example.com/page` | ✅ 同源 | 路径不同不影响 |
| `http://www.example.com` | ❌ 跨域 | 协议不同 |
| `https://api.example.com` | ❌ 跨域 | 子域名不同 |
| `https://www.example.com:8080` | ❌ 跨域 | 端口不同 |

## 同源策略限制了什么

| 限制项 | 说明 |
|--------|------|
| Cookie/localStorage | 无法读取跨域页面的存储 |
| DOM | 无法访问跨域页面的 DOM |
| AJAX | 无法发送跨域请求（或无法读取响应） |

**不受限制的**：`<img>`、`<script>`、`<link>`、`<iframe>`（加载不受限，但 JS 访问受限）

## 跨域解决方案

### 方案对比

| 方案 | 适用场景 | 复杂度 |
|------|---------|--------|
| **CORS** | 前后端配合，主流方案 | ⭐ |
| **代理** | 开发环境、Nginx 生产 | ⭐⭐ |
| **JSONP** | 兼容老浏览器，仅 GET | ⭐ |
| **postMessage** | 页面间通信 | ⭐⭐ |

### 1. CORS（主流方案）

**原理**：服务端设置响应头，告诉浏览器允许跨域访问。

#### 简单请求

满足以下条件的请求，浏览器直接发送：

- 方法：`GET`、`POST`、`HEAD`
- 头部：仅限 `Accept`、`Accept-Language`、`Content-Language`、`Content-Type`（且值为 `text/plain`、`multipart/form-data`、`application/x-www-form-urlencoded`）

```
浏览器                          服务器
  │                              │
  │ ─── GET /api ───────────→    │
  │     Origin: https://a.com    │
  │                              │
  │ ←── 200 OK ─────────────     │
  │     Access-Control-Allow-Origin: https://a.com
```

#### 预检请求（Preflight）

不满足简单请求条件时，先发 OPTIONS 探测：

```
浏览器                          服务器
  │                              │
  │ ─── OPTIONS /api ───────→    │  预检请求
  │     Origin: https://a.com    │
  │     Access-Control-Request-Method: PUT
  │                              │
  │ ←── 204 ────────────────     │  预检响应
  │     Access-Control-Allow-Origin: https://a.com
  │     Access-Control-Allow-Methods: PUT, POST
  │     Access-Control-Max-Age: 86400
  │                              │
  │ ─── PUT /api ───────────→    │  正式请求
  │                              │
  │ ←── 200 OK ─────────────     │
```

#### 服务端配置

```javascript
// Express
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', 'https://a.com'); // 或 * 允许所有
  res.header('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  res.header('Access-Control-Allow-Headers', 'Content-Type, Authorization');
  res.header('Access-Control-Allow-Credentials', 'true'); // 允许携带 Cookie
  res.header('Access-Control-Max-Age', '86400'); // 预检缓存时间

  if (req.method === 'OPTIONS') {
    return res.sendStatus(204);
  }
  next();
});
```

```nginx
# Nginx
location /api {
    add_header Access-Control-Allow-Origin https://a.com;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE";
    add_header Access-Control-Allow-Headers "Content-Type, Authorization";
    add_header Access-Control-Allow-Credentials true;

    if ($request_method = OPTIONS) {
        return 204;
    }
}
```

#### 携带 Cookie

```javascript
// 前端必须设置
fetch('https://api.com/data', {
  credentials: 'include'  // 携带 Cookie
});

// 服务端必须设置
Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: https://a.com  // 不能用 *
```

### 2. 代理（开发常用）

**原理**：同源策略是浏览器限制，服务器之间没有跨域问题。

```
浏览器 ──→ 同源代理服务器 ──→ 目标 API
        （无跨域）        （服务器间无限制）
```

#### Webpack DevServer

```javascript
// webpack.config.js
devServer: {
  proxy: {
    '/api': {
      target: 'https://api.example.com',
      changeOrigin: true,
      pathRewrite: { '^/api': '' }
    }
  }
}
```

#### Vite

```javascript
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': {
        target: 'https://api.example.com',
        changeOrigin: true,
        rewrite: path => path.replace(/^\/api/, '')
      }
    }
  }
}
```

#### Nginx（生产环境）

```nginx
location /api {
    proxy_pass https://api.example.com;
    proxy_set_header Host api.example.com;
    proxy_set_header X-Real-IP $remote_addr;
}
```

### 3. JSONP（兼容方案）

**原理**：利用 `<script>` 不受同源限制的特性。

**限制**：只支持 GET 请求。

```javascript
// 前端
function handleResponse(data) {
  console.log(data);
}

const script = document.createElement('script');
script.src = 'https://api.com/data?callback=handleResponse';
document.body.appendChild(script);

// 服务端返回
handleResponse({"name": "test", "value": 123})
```

### 4. postMessage（页面通信）

**场景**：iframe 嵌套、window.open 打开的页面之间通信。

```javascript
// 发送方（父页面）
const iframe = document.getElementById('iframe');
iframe.contentWindow.postMessage({ type: 'getData' }, 'https://b.com');

// 接收方（iframe）
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://a.com') return; // 验证来源
  console.log(e.data);

  // 回复
  e.source.postMessage({ result: 'ok' }, e.origin);
});
```

## 常见面试题

### Q1：什么是同源策略？为什么需要？

**答**：同源策略是浏览器的安全机制，要求协议、域名、端口完全相同才算同源。目的是防止恶意网站读取其他网站的敏感数据（如 Cookie、DOM）。

### Q2：简单请求和预检请求的区别？

| 对比项 | 简单请求 | 预检请求 |
|--------|---------|---------|
| 触发条件 | GET/POST/HEAD + 简单头部 | PUT/DELETE 或自定义头部 |
| 请求次数 | 1 次 | 2 次（OPTIONS + 正式） |
| 是否可缓存 | - | 可通过 Max-Age 缓存 |

### Q3：CORS 和 JSONP 的区别？

| 对比项 | CORS | JSONP |
|--------|------|-------|
| 请求方法 | 所有 | 仅 GET |
| 实现位置 | 服务端配置 | 前后端配合 |
| 安全性 | 高 | 低（XSS 风险） |
| 浏览器支持 | IE10+ | 所有 |

### Q4：开发和生产环境如何处理跨域？

- **开发**：Webpack/Vite 代理
- **生产**：Nginx 反向代理 或 CORS
