## 核心概念

**垃圾回收（GC）**：自动回收不再使用的内存，防止内存泄漏。

**V8 内存结构**：

```
┌─────────────────────────────────────┐
│              V8 堆内存               │
├─────────────────┬───────────────────┤
│     新生代       │       老生代       │
│   (1-8MB)       │    (默认 1.4GB)    │
├────────┬────────┼───────────────────┤
│  From  │   To   │                   │
│  空间  │  空间   │                   │
└────────┴────────┴───────────────────┘
```

## 分代回收策略

| 代 | 特点 | 回收算法 | 触发条件 |
|----|------|---------|---------|
| **新生代** | 存活时间短，空间小 | Scavenge（复制算法） | From 空间满 |
| **老生代** | 存活时间长，空间大 | Mark-Sweep + Mark-Compact | 空间不足 |

## 新生代回收：Scavenge

### 算法原理

将新生代分为两个等大空间：From（使用中）和 To（空闲）。

```
回收前：
┌─────────────────┬─────────────────┐
│  From（有对象）   │   To（空闲）     │
│  [A][B][C][D]   │                 │
└─────────────────┴─────────────────┘

回收后：（假设 A、C 存活）
┌─────────────────┬─────────────────┐
│   From（空闲）   │  To（有对象）    │
│                 │   [A][C]        │
└─────────────────┴─────────────────┘

下次分配时 From/To 角色互换
```

### 执行步骤

1. 标记 From 空间中的存活对象
2. 将存活对象**复制**到 To 空间（同时整理，无碎片）
3. 清空 From 空间
4. From 和 To 角色互换

### 晋升到老生代

对象满足以下条件之一，晋升到老生代：

1. **经历过一次 Scavenge** 仍然存活
2. **To 空间使用超过 25%**（保证下次 From 有足够空间）

## 老生代回收：Mark-Sweep + Mark-Compact

### Mark-Sweep（标记清除）

```
第一阶段：标记
┌───────────────────────────────┐
│ [A✓] [B✗] [C✓] [D✗] [E✓]     │
└───────────────────────────────┘
  ✓ 可达（存活）  ✗ 不可达（垃圾）

第二阶段：清除
┌───────────────────────────────┐
│ [A ] [  ] [C ] [  ] [E ]     │
└───────────────────────────────┘
  产生内存碎片
```

**问题**：清除后产生不连续的内存碎片，大对象可能无法分配。

### Mark-Compact（标记整理）

```
标记后整理：
┌───────────────────────────────┐
│ [A✓] [B✗] [C✓] [D✗] [E✓]     │
└───────────────────────────────┘
          ↓ 整理
┌───────────────────────────────┐
│ [A ] [C ] [E ] [          ]   │
└───────────────────────────────┘
  存活对象移到一端，连续空间
```

### 何时使用

- **Mark-Sweep**：内存碎片可接受时使用，速度快
- **Mark-Compact**：碎片过多，需要整理时使用，速度慢

## 增量标记与并发回收

### 问题：Stop-The-World

GC 执行时需要暂停 JS 执行，老生代数据量大时会造成明显卡顿。

### 解决方案

| 策略 | 原理 | 效果 |
|------|------|------|
| **增量标记** | 将标记分成多个小步，与 JS 交替执行 | 减少单次停顿 |
| **并发标记** | 标记在辅助线程进行，不阻塞主线程 | 几乎无停顿 |
| **并行回收** | 多个辅助线程同时进行回收 | 加快回收速度 |

```
传统 GC：
JS执行 ──────────┐
                 │ GC（长停顿）
                 └───────────────── JS执行

增量标记：
JS ─── GC ─── JS ─── GC ─── JS ─── GC ─── JS
      (小)        (小)        (小)
```

## 内存泄漏

### 什么是内存泄漏

不再使用的内存没有被回收，持续占用内存。

### 常见场景

#### 1. 意外的全局变量

```javascript
// ❌ 忘记 var/let/const
function leak() {
  leakedVar = 'I am global';  // 挂载到 window
}

// ✅ 使用严格模式
'use strict';
function safe() {
  let localVar = 'I am local';
}
```

#### 2. 未清理的定时器

```javascript
// ❌ 组件卸载后定时器仍在运行
function Component() {
  setInterval(() => {
    // 引用了组件内的变量
  }, 1000);
}

// ✅ 清理定时器
function Component() {
  useEffect(() => {
    const timer = setInterval(() => {}, 1000);
    return () => clearInterval(timer);  // 清理
  }, []);
}
```

#### 3. 未移除的事件监听

```javascript
// ❌ 事件监听未移除
element.addEventListener('click', handler);

// ✅ 移除监听
element.addEventListener('click', handler);
// 组件卸载时
element.removeEventListener('click', handler);
```

#### 4. 闭包引用

```javascript
// ❌ 闭包持有大对象引用
function createClosure() {
  const largeData = new Array(1000000).fill('x');
  return function() {
    console.log(largeData.length);  // 闭包持有 largeData
  };
}
const closure = createClosure();  // largeData 无法被回收

// ✅ 用完置空
function createClosure() {
  let largeData = new Array(1000000).fill('x');
  const length = largeData.length;
  largeData = null;  // 解除引用
  return function() {
    console.log(length);
  };
}
```

#### 5. DOM 引用

```javascript
// ❌ DOM 元素删除后，JS 仍持有引用
const elements = {
  button: document.getElementById('button')
};
document.body.removeChild(document.getElementById('button'));
// elements.button 仍然存在，DOM 无法回收

// ✅ 同时清除 JS 引用
document.body.removeChild(document.getElementById('button'));
elements.button = null;
```

#### 6. console.log

```javascript
// ❌ 控制台打印的对象会被持有
console.log(hugeObject);

// ✅ 生产环境移除 console
// 或只打印必要信息
console.log(hugeObject.id);
```

## 内存泄漏排查

### Chrome DevTools

1. **Memory 面板** → Take Heap Snapshot
2. 对比多次快照，查看增长的对象
3. 查看 Retainers（谁持有这个对象的引用）

### Performance Monitor

1. DevTools → More Tools → Performance Monitor
2. 观察 JS Heap Size 是否持续增长

### 代码检测

```javascript
// 监控内存使用
if (performance.memory) {
  console.log('已用内存:', performance.memory.usedJSHeapSize / 1024 / 1024, 'MB');
  console.log('内存限制:', performance.memory.jsHeapSizeLimit / 1024 / 1024, 'MB');
}
```

## 常见面试题

### Q1：V8 的垃圾回收机制？

V8 采用**分代回收**策略：
- **新生代**：Scavenge 算法（复制），空间小，回收快
- **老生代**：Mark-Sweep + Mark-Compact，空间大，增量/并发回收

### Q2：为什么要分新生代和老生代？

- 大部分对象"朝生夕死"，适合快速复制回收
- 少数长期存活对象放入老生代，减少频繁复制开销
- 不同生命周期的对象用不同算法，提高效率

### Q3：什么对象会晋升到老生代？

1. 经历过一次 Scavenge 仍存活
2. To 空间使用超过 25%

### Q4：如何避免内存泄漏？

| 场景 | 解决方案 |
|------|---------|
| 全局变量 | 使用 `let/const`，严格模式 |
| 定时器 | 组件卸载时 `clearInterval` |
| 事件监听 | 组件卸载时 `removeEventListener` |
| 闭包 | 及时解除不需要的引用 |
| DOM 引用 | 删除 DOM 同时清除 JS 引用 |

### Q5：Mark-Sweep 和 Mark-Compact 的区别？

- **Mark-Sweep**：标记存活对象，清除垃圾，会产生碎片
- **Mark-Compact**：清除后整理，存活对象移到一端，无碎片但更慢
