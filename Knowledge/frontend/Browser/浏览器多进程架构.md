## 核心概念

**进程 vs 线程**：

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 定义 | 资源分配的最小单位 | CPU 调度的最小单位 |
| 内存 | 独立内存空间 | 共享进程内存 |
| 通信 | IPC（较慢） | 直接访问（快） |
| 崩溃影响 | 不影响其他进程 | 可能导致整个进程崩溃 |

## Chrome 多进程架构

```
┌─────────────────────────────────────────────────────┐
│                    浏览器进程                         │
│  ┌─────────┬─────────┬─────────┬─────────┐         │
│  │ UI线程  │网络线程  │存储线程  │ 其他... │         │
│  └─────────┴─────────┴─────────┴─────────┘         │
└─────────────────────────────────────────────────────┘
           │              │              │
           ▼              ▼              ▼
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  渲染进程    │  │  渲染进程    │  │   GPU进程   │
│  (Tab 1)    │  │  (Tab 2)    │  │             │
└─────────────┘  └─────────────┘  └─────────────┘
                                         │
┌─────────────┐  ┌─────────────┐         │
│  网络进程    │  │  插件进程    │         │
│             │  │             │         │
└─────────────┘  └─────────────┘         │
```

## 主要进程

| 进程 | 职责 | 数量 |
|------|------|------|
| **浏览器进程** | 界面、用户交互、子进程管理 | 1 个 |
| **渲染进程** | 页面渲染、JS 执行、Web Worker | 多个（每个 Tab 或站点） |
| **GPU 进程** | 3D 渲染、页面合成 | 1 个 |
| **网络进程** | 网络请求 | 1 个 |
| **插件进程** | 运行插件（如 Flash） | 每插件 1 个 |

## 浏览器进程

**作用**：管理整个浏览器，协调其他进程。

### 主要线程

| 线程 | 职责 |
|------|------|
| **UI 线程** | 绘制工具栏、地址栏等界面 |
| **网络线程** | 处理网络请求 |
| **存储线程** | 控制文件读写 |

### 导航流程

```
用户输入 URL
    │
    ▼
UI 线程判断：是 URL 还是搜索？
    │
    ▼
通知网络线程发起请求
    │
    ▼
网络线程完成请求
    │
    ▼
判断响应类型（HTML → 渲染进程）
    │
    ▼
创建/复用渲染进程
    │
    ▼
渲染进程开始解析和渲染
```

## 渲染进程

**作用**：解析 HTML/CSS、执行 JavaScript、渲染页面。

### 主要线程

| 线程 | 职责 |
|------|------|
| **主线程** | DOM 解析、CSS 计算、JS 执行、布局、绑定事件 |
| **合成线程** | 将图层分块、光栅化、合成帧 |
| **光栅化线程（池）** | 将图块转为位图 |
| **Worker 线程** | 执行 Web Worker |

### 渲染流程

```
主线程：
HTML → DOM → 样式计算 → 布局 → 分层 → 绘制指令
                                       │
                                       ▼
合成线程：
分块 → 光栅化（GPU 进程）→ 合成帧 → 显示
```

### 进程隔离策略

| 策略 | 说明 |
|------|------|
| **Site Isolation** | 不同站点使用不同渲染进程 |
| **process-per-tab** | 每个标签页一个进程（旧策略） |
| **process-per-site** | 同站点共享进程（节省内存） |

**Site Isolation 的好处**：
- 安全：防止跨站攻击（Spectre）
- 稳定：一个站点崩溃不影响其他

## GPU 进程

**作用**：处理所有 GPU 任务。

### 职责

- 页面图层合成
- CSS 3D 变换、动画
- WebGL 渲染
- 视频解码

### 合成加速

```css
/* 这些属性会创建新的合成层，由 GPU 处理 */
.element {
  transform: translateZ(0);
  will-change: transform;
  opacity: 0.5;  /* 配合 transform */
}
```

**好处**：合成层变化只需 GPU 重新合成，不需要主线程参与，性能高。

## 网络进程

**作用**：处理所有网络请求。

### 职责

- DNS 查询
- TCP/TLS 连接
- HTTP 请求/响应
- 缓存管理

### 与渲染进程的配合

```
渲染进程                网络进程               服务器
    │                      │                    │
    │ ── 请求资源 ────→    │                    │
    │                      │ ── HTTP 请求 ──→   │
    │                      │                    │
    │                      │ ←── HTTP 响应 ──   │
    │ ←── 返回数据 ────    │                    │
```

## 进程间通信 (IPC)

### Mojo

Chrome 使用 Mojo 进行进程间通信。

```
渲染进程                     浏览器进程
    │                           │
    │ ── Mojo 消息 ──────────→  │
    │                           │
    │ ←── Mojo 响应 ──────────  │
```

### 通信场景

| 场景 | 通信方向 |
|------|---------|
| 发起网络请求 | 渲染进程 → 浏览器进程 → 网络进程 |
| 打开新标签页 | 渲染进程 → 浏览器进程 |
| 访问 Cookie | 渲染进程 → 浏览器进程 |
| GPU 绑定 | 渲染进程 → GPU 进程 |

## 为什么采用多进程架构

### 优点

| 优点 | 说明 |
|------|------|
| **稳定性** | 一个标签页崩溃不影响其他 |
| **安全性** | 渲染进程沙箱化，限制权限 |
| **流畅性** | 充分利用多核 CPU |

### 缺点

| 缺点 | 说明 |
|------|------|
| **内存占用高** | 每个进程独立内存空间 |
| **启动慢** | 创建进程有开销 |

### Chrome 的优化

- **进程复用**：同站点标签页共享渲染进程
- **内存回收**：不活跃标签页释放部分内存
- **延迟创建**：按需创建 GPU、网络进程

## 沙箱机制

### 原理

渲染进程在**沙箱**中运行，限制其访问系统资源。

```
┌─────────────────────────────────┐
│          操作系统               │
│  ┌───────────────────────────┐ │
│  │       沙箱                 │ │
│  │  ┌───────────────────┐   │ │
│  │  │    渲染进程        │   │ │
│  │  │  - 无法访问文件    │   │ │
│  │  │  - 无法访问网络    │   │ │
│  │  │  - 无法调用系统API │   │ │
│  │  └───────────────────┘   │ │
│  └───────────────────────────┘ │
└─────────────────────────────────┘
```

### 限制项

渲染进程**无法**直接：
- 读写文件系统
- 发起网络请求
- 访问摄像头/麦克风
- 调用系统原生 API

必须通过 IPC 请求浏览器进程代为执行。

## 常见面试题

### Q1：Chrome 有哪些进程？

1. **浏览器进程**：UI、子进程管理
2. **渲染进程**：页面渲染、JS 执行
3. **GPU 进程**：图形渲染
4. **网络进程**：网络请求
5. **插件进程**：运行插件

### Q2：渲染进程包含哪些线程？

1. **主线程**：DOM、CSS、JS、布局
2. **合成线程**：图层合成
3. **光栅化线程**：图块转位图
4. **Worker 线程**：Web Worker

### Q3：为什么 JS 是单线程的？

- 避免 DOM 操作冲突（多线程同时修改 DOM）
- 简化开发模型
- 可以通过 Web Worker 实现多线程计算

### Q4：为什么 CSS 动画比 JS 动画流畅？

| 动画类型 | 执行线程 | 优势 |
|---------|---------|------|
| JS 动画 | 主线程 | 容易被阻塞 |
| CSS transform/opacity | 合成线程 | 不占用主线程 |

CSS 的 `transform` 和 `opacity` 动画只在合成线程执行，不影响主线程，所以更流畅。

### Q5：多进程和多线程的区别？

| 对比项 | 多进程 | 多线程 |
|--------|--------|--------|
| 内存 | 独立（隔离好） | 共享（通信快） |
| 崩溃 | 互不影响 | 可能连带 |
| 开销 | 大 | 小 |
| 通信 | IPC（慢） | 内存共享（快） |
