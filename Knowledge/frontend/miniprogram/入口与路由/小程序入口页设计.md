## 结论

小程序需要一个统一的入口页（`page/index/index`），承担三件事：

1. **静默登录**：用户无感知地完成登录
2. **参数解析**：处理分享链接和小程序码的参数
3. **路由分发**：跳转到真正的目标页面

这个页面不渲染任何 UI，只是一个"跳板"。

## 为什么需要入口页

### 问题1：分享链接的落地页

用户点击分享链接进入小程序，微信会打开 path 指定的页面。

如果分享的是直播间，path 是 `page/live/index`。但直播间页面依赖用户登录状态——还没登录就打开页面，会出问题。

**解决方案**：所有分享链接都指向入口页，入口页完成登录后再跳转。

```typescript
// 分享配置
useShareAppMessage(() => ({
  title: '直播间',
  path: `page/index/index?pageKey=LIVE&activityId=${activityId}`,  // 指向入口页
}));
```

### 问题2：小程序码的参数限制

小程序码的 scene 参数**最多 32 个字符**。

一个直播间链接可能需要：`activityId=123456&storeId=789&userId=abc`——早就超了。

**解决方案**：后端生成短 ID，入口页调用接口解析。

```
小程序码 scene=abc123
     ↓
入口页调用 /qrcode/get-scene-by-id
     ↓
后端返回完整参数：activityId=123456&storeId=789&pageKey=LIVE
     ↓
入口页跳转到直播页
```

### 问题3：登录态初始化

很多页面需要用户信息（token、userId），但小程序启动时用户还没登录。

**解决方案**：入口页统一完成登录初始化。

## 入口页的实现

```tsx
// page/index/index.tsx
export default function Index() {
  useLoad(async (options) => {
    // 1. 初始化登录（静默登录，用户无感知）
    const userInfo = await getAuthState().initAuth({ waitPending: true });

    // 2. 初始化日志（登录后才有 userId）
    clsLogger.init({
      generateBaseFields: () => ({
        userId: userInfo.id,
        openId: userInfo.openId,
      }),
    });

    // 3. 解析参数
    let { pageKey, scene, ...rest } = options;

    // 如果有 scene 参数，调用接口解析
    if (scene) {
      const res = await getSceneById({ id: scene });
      if (res.success && res.data?.scene) {
        const sceneParams = parseSceneParams(res.data.scene);
        pageKey = sceneParams.pageKey || 'HOME';
        Object.assign(rest, sceneParams);
      }
    }

    // 4. 路由分发
    const targetPage = pageKey ? PAGE_KEYS[pageKey] : PAGE_KEYS.HOME;
    toPage(targetPage, rest, 'redirect');
  });

  // 不渲染任何 UI
  return <></>;
}
```

### 参数来源

| 场景 | options 内容 | 处理方式 |
|------|-------------|----------|
| 分享链接点击 | `pageKey=LIVE&activityId=xxx` | 直接使用 |
| 小程序码扫码 | `scene=abc123` | 调接口解析 |
| 直接打开小程序 | 空 | 跳转首页 |

### 路由分发逻辑

```typescript
// 页面配置：区分原生页面和 WebView 页面
const PAGE_CONFIG_MAP = {
  HOME: { path: '/page/home/index', webview: false },
  PROFILE: { path: '/page/profile/index', webview: false },
  LIVE: { path: '/scene', webview: true },  // WebView 页面
  ORDER_LIST: { path: '/order-list', webview: true },
  // ...
};

// 跳转逻辑
const toPage = (pageKey, query, type) => {
  const page = PAGE_CONFIG_MAP[pageKey];

  if (page.webview) {
    // WebView 页面：跳转到 web-view 组件页
    const url = `/page/web-view/index?url=${encodeURIComponent(page.path + '?' + queryStr)}`;
    Taro.redirectTo({ url });
  } else {
    // 原生页面：直接跳转
    Taro.redirectTo({ url: page.path + '?' + queryStr });
  }
};
```

## 静默登录的实现

小程序登录不需要用户操作，后台完成：

```typescript
const getUserInfoByCode = async () => {
  // 1. 获取微信 code
  const wxCode = await getWxCode();  // 封装 Taro.login()

  // 2. 用 code 换用户信息
  const userRes = await fetchUserLogin({
    jsCode: wxCode,
    appId: Taro.getAccountInfoSync().miniProgram.appId,
  });

  // 3. 保存 token 和用户信息
  beLinkHttp.setToken(userRes.data.token);
  return userRes.data.userInfo;
};
```

### 防止并发登录

入口页是第一个加载的页面，但可能有多个地方同时调用 `initAuth()`。

```typescript
let loginPromise: Promise<UserInfo> | null = null;

const initAuth = async () => {
  // 如果正在登录，复用当前 Promise
  if (loginPromise) {
    return loginPromise;
  }

  // 创建新的登录 Promise
  loginPromise = getUserInfoByCode();

  loginPromise.finally(() => {
    loginPromise = null;
  });

  return loginPromise;
};
```

## scene 参数解析

### 后端生成 scene

```typescript
// 后端接口：生成小程序码
POST /qrcode/create
{
  "params": "pageKey=LIVE&activityId=123456&storeId=789"
}

// 返回
{
  "sceneId": "abc123",  // 32字符以内
  "qrcodeUrl": "https://..."
}
```

### 前端解析 scene

```typescript
const parseSceneParams = (sceneStr: string): Record<string, string> => {
  const params: Record<string, string> = {};
  decodeURIComponent(sceneStr)
    .split('&')
    .forEach((pair) => {
      const [key, value] = pair.split('=');
      if (key) {
        params[key] = value || '';
      }
    });
  return params;
};

// 使用
if (scene) {
  const res = await getSceneById({ id: scene });
  // res.data.scene = "pageKey=LIVE&activityId=123456"
  const sceneParams = parseSceneParams(res.data.scene);
  // sceneParams = { pageKey: 'LIVE', activityId: '123456' }
}
```

## 分享桥页面

有些场景需要用户主动点击"分享"按钮，不能直接分享。这时需要一个"分享桥"页面。

```tsx
// page/share-bridge/index.tsx
export default function ShareBridge() {
  const [activityId, setActivityId] = useState<string>();

  useLoad((options) => {
    setActivityId(options.activityId);
  });

  // 配置分享信息
  useShareAppMessage(() => ({
    title: `直播间 - ${liveInfo.name}`,
    path: `page/index/index?pageKey=LIVE&activityId=${activityId}`,
    imageUrl: liveInfo.shareCover,
  }));

  return (
    <View>
      <Button openType='share'>转发直播间</Button>
    </View>
  );
}
```

**流程**：

```
用户点击"分享"按钮
     ↓
跳转到分享桥页面
     ↓
用户点击"转发"按钮
     ↓
微信分享弹窗
     ↓
好友点击分享卡片
     ↓
进入入口页（page/index/index）
     ↓
登录 + 参数解析 + 跳转到直播页
```

## 企业微信拦截

### 为什么要拦截

企业微信可以扫描小程序码打开小程序，但行为和微信不同：

1. **可以复制 WebView 链接**：企业微信打开小程序后，进入 WebView 页面，用户可以长按复制 H5 的 URL
2. **链接泄露风险**：复制出来的 URL 包含 token、userId 等敏感参数，可以在外部浏览器直接打开
3. **绕过小程序限制**：原本只能在小程序内访问的页面，通过复制链接可以在任意环境访问

```
企业微信扫码
     ↓
打开小程序 → 进入 WebView
     ↓
长按 → 复制链接
     ↓
粘贴到浏览器 → 直接访问 H5（绕过了小程序）
```

### 检测企业微信环境

```typescript
/**
 * 判断是否在企业微信环境
 * 企业微信的 User-Agent 包含 wxwork
 */
const isWxWork = (): boolean => {
  const ua = navigator.userAgent.toLowerCase();
  return ua.includes('wxwork');
};
```

也可以用 Taro 的 API：

```typescript
const isWxWork = (): boolean => {
  const systemInfo = Taro.getSystemInfoSync();
  // 企业微信环境下 environment 为 'wxwork'
  return systemInfo.environment === 'wxwork';
};
```

### 拦截处理

在入口页判断，如果是企业微信环境，直接跳转到提示页：

```typescript
// page/index/index.tsx
useLoad(async (options) => {
  // 企业微信拦截 - 必须放在最前面
  if (isWxWork()) {
    toPage(PAGE_KEYS.TIPS, {
      tip: '请使用微信扫码打开',
      subTip: '企业微信暂不支持此功能',
    }, 'redirect');
    return;  // 直接返回，不执行后续登录和跳转逻辑
  }

  // 正常流程：登录 → 参数解析 → 路由分发
  const userInfo = await getAuthState().initAuth({ waitPending: true });
  // ...
});
```

### 提示页设计

```tsx
// page/tips/index.tsx
export default function Tips() {
  const [tip, setTip] = useState('');
  const [subTip, setSubTip] = useState('');

  useLoad((options) => {
    setTip(decodeURIComponent(options.tip || ''));
    setSubTip(decodeURIComponent(options.subTip || ''));
  });

  return (
    <View className='tips-page'>
      <View className='tip-icon'>⚠️</View>
      <View className='tip-text'>{tip}</View>
      {subTip && <View className='sub-tip-text'>{subTip}</View>}
    </View>
  );
}
```

### 为什么不在 WebView 层拦截

你可能会想：在 WebView 页面拦截不是更好吗？

**不行**，原因：

1. **已经晚了**：到 WebView 页面时，URL 已经构建好了，包含了敏感参数
2. **入口页是第一道关卡**：所有外部链接都经过入口页，在这里拦截最有效
3. **避免信息泄露**：在入口页拦截，连 WebView 都不会加载，用户拿不到任何 H5 链接

### H5 端二次防护

虽然入口页已经拦截，但 H5 端也应该有防护（防止直接访问 H5）：

```typescript
// H5 端检测是否在小程序 WebView 环境
const isInMiniProgram = (): boolean => {
  // 检查 URL 参数中是否有小程序传来的标识
  const fromMini = searchParams.get('fromMini');

  // 或者检查 user-agent
  const ua = navigator.userAgent.toLowerCase();
  return ua.includes('miniprogram') || fromMini === 'true';
};

// 如果不在小程序环境，拒绝访问
if (!isInMiniProgram()) {
  // 显示提示或重定向
}
```

## 经验总结

| 设计点 | 做法 |
|--------|------|
| 统一入口 | 所有外部链接都指向 `page/index/index` |
| 登录前置 | 入口页完成登录，再跳转目标页 |
| 参数透传 | 入口页解析参数后，原样传给目标页 |
| scene 解析 | 后端存完整参数，前端用短 ID 换取 |
| 路由配置化 | 原生页面和 WebView 页面统一管理 |

## 为什么不直接打开目标页

你可能会想：分享直接指向直播页不行吗？在直播页里登录不行吗？

可以，但会有问题：

1. **登录时序**：页面渲染依赖用户数据，没登录就渲染会闪烁或报错
2. **代码重复**：每个页面都要写登录逻辑
3. **参数解析**：每个页面都要处理 scene 参数
4. **难以维护**：新增页面要记得加登录逻辑

统一入口页，一次解决所有问题。
